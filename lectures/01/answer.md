## 演習

- 使ったモデル：gemini-3.5-flash-lite（既定）
- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：「講座によって異なる」と前置きしたうえで、一般論として「レベル1＝基礎・入門（講義のコードを動かす）、レベル2＝応用・標準（条件を変える）、レベル3＝発展・挑戦（応用問題や自由課題）」という難易度別の3段階課題だと説明した。最後に、講座の案内文やコミュニティで確認するよう勧めていた。
- 用語集の正しい意味と比べて気づいたこと：
  - 用語集（homework-levels）の定義は「基礎・実装・発展の3段階があり、どれか1つに取り組めば完了。原則として採点はしない」。モデルの回答は「3段階ある」という点だけは合っていたが、「実装（自分でコードを書く）」という区分がなく、最も大事な「どれか1つで完了」という点も抜けていた。一般論から組み立てた、もっともらしい答えだった。
  - ほかの講座固有の質問では、答え方が分かれた。「lecNN タグ」は「講義回を識別する管理用タグ（教材の整理、質問時の指定、Slackチャンネル名など）」と自信を持って答えた。しかし用語集では「各回の演習開始時点のコードに付けた Git タグで、そこからブランチを作れば前の回が終わっていなくても始められる」もので、用途がまったく違う。一方「AIE2026の第2回では何を学びますか？」には「情報の範囲外で特定できない」と正直に答えた（実際はファインチューニングとLoRA）。
  - 一般的な用語の「LoRA」は、元のモデルを凍結して差分だけを学習する仕組みや、省リソースで済むことなど、おおむね正しく説明できていた。
  - 知らないことを「知らない」と答えるか、もっともらしく作るかは質問によって変わり、利用者からは見分けにくい。講座固有の情報は、資料を検索して根拠付きで答える仕組み（第3回以降のエージェントやRAG）が必要だと感じた。
- 表示できたトークン数（入力 / 出力）：上の実行は改修前の main ブランチで行ったため、トークン数は表示されていない。改修後の lec01 ブランチで同じ「3レベル」の質問をすると、入力 21 / 出力 757 だった。このときの回答は「難易度別」「習得ステップ別」「必須・選択別」の3パターンを並べたもので、1回目とは内容も長さも違っていた。同じ質問でも実行ごとに答えが変わることを確認できた

## 宿題

- 取り組んだレベル：実装
- 使ったモデル：gemini-3.5-flash-lite（既定）
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした。`client.chats.create` で作ったチャットに `send_message` で質問を送ると、それまでの質問と返答が履歴として一緒に送られる。空行か `exit` で終了する。
  - 演習の TODO として、各回答のあとに入力・出力トークン数を表示するようにした（単発・会話の両方）。
  - API エラー（レート制限など）が起きても会話が終わらず、続けて質問できるようにした。
  - APIキーなしで動くテスト `tests/test_ask.py` を追加し、履歴が残ること・トークン表示を確認した（`uv run pytest -q` で全件成功）。
- 結果：
  - 実行コマンド：`uv run python -m app.ask --chat`
  - 1問目「LoRAとは何ですか？」→ Low-Rank Adaptation の略で、元のモデルを固定して小さな追加パラメータだけを学習する技術だと説明した（必要メモリが少ない、学習が短い、ファイルが数MB〜数十MB、画像生成やLLMで使われる）。トークン数は入力 7 / 出力 480。
  - 2問目「それを中学生にも分かるように一文で言い換えて」→「AIの頭全体を作り直すのではなく、ちょっとした付箋を貼るだけで新しい得意分野を覚えさせられる技術」と答えた。「それ」が1問目の LoRA を指すと理解しており、会話履歴が引き継がれていることを確認できた。トークン数は入力 500 / 出力 41。
  - `exit` で終了すると「2 往復、履歴 4 件」と表示され、質問2件と回答2件が履歴に残っていた。
  - 単発モードで同じ2問目だけを送る比較は、今回は実行していない。
- 気づき・疑問：
  - 2問目の質問文は短いのに、入力トークンは 7 から 500 に増えた。500 は「1問目の質問 7 ＋ 1問目の回答 480 ＋ 2問目の質問」とほぼ一致する。モデル自体は会話を覚えておらず、毎回それまでの履歴をまとめて送り直していることが数字で分かった。
  - そのため、長い回答を受けたあとの会話ほど入力が膨らみ、コストや応答時間、無料枠の消費が増えると考えられる。長い会話では、古い履歴を要約したり捨てたりする工夫が必要になりそうだ。
  - 改修した単発モードでは、トークン数が回答本文より先に表示される。トークン数は回答後に表示するほうが読みやすいので、表示の順番は今後直したい。
